# ADR-0002 — License GPL-3.0-or-later; dependency license policy; AI-generated code

- **Status:** Accepted
- **Date:** 2026-10-28

## Context

Orchestra is open source. The owner chose a strong copyleft license so that improvements stay
free. Dependencies must therefore be license-compatible with distribution under GPL-3.0. A large
part of the code is written with AI assistance, which raises an open legal question.

## Decision

1. **Project license: GPL-3.0-or-later.** The full text is in `LICENSE` (official text from
   gnu.org). Every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later` (or the
   `#` comment equivalent in TOML/shell files). Manifests declare `license = "GPL-3.0-or-later"`.
2. **Dependency licenses** are enforced by `cargo deny check licenses` (`deny.toml`). Allowed:
   GPL-3.0-or-later/-only, GPL-2.0-or-later, LGPL-2.1-or-later, LGPL-3.0, MPL-2.0, Apache-2.0
   (also WITH LLVM-exception), MIT, MIT-0, BSD-2/3-Clause, 0BSD, ISC, Zlib, BSL-1.0, Unicode-3.0,
   CC0-1.0, Unlicense. Anything else needs an amendment of this ADR.
   - Sources: FSF list of GPL-compatible licenses, <https://www.gnu.org/licenses/license-list.html>;
     ASF on Apache-2.0 and GPLv3, <https://www.apache.org/licenses/GPL-compatibility.html>;
     MPL-2.0 §3.3 "Secondary Licenses", <https://www.mozilla.org/en-US/MPL/2.0/>.
   - **GPL-2.0-only is NOT compatible** with GPL-3.0 and is therefore excluded.
3. **Fonts** bundled in the program or the guides must be under the SIL Open Font License 1.1 (or
   a more permissive license). OFL fonts may be bundled with GPL software (the FSF lists OFL as a
   free license for fonts); they are not "linked code", so the OFL is not added to the code
   allow-list but checked by hand and recorded in `assets/fonts/README.md`.
4. **Sources:** only crates.io (`cargo deny check sources`); git dependencies need an exception.
5. **AI-generated code — known uncertainty.** In several jurisdictions, copyright protection of
   output generated by an AI system without sufficient human creative contribution is uncertain
   (for example, the U.S. Copyright Office's 2025 report on copyrightability concluded that purely
   AI-generated material is not protectable, while human selection, arrangement and modification
   can be). We cannot resolve this; we mitigate it:
   - the human owner directs the design (ADRs, reviews, decisions) and the commits record human
     authorship and AI co-authorship (`Co-Authored-By` trailers) transparently;
   - the GPL notice is applied to the whole work regardless, so whatever *is* protectable is under
     the GPL, and nothing in the repository is offered under different terms;
   - no code is copied from sources with incompatible licenses; AI suggestions that look like
     verbatim copies of third-party code are rejected.
   This is not legal advice; if the project gains commercial relevance, seek a lawyer's opinion.

## Alternatives rejected

- **MIT/Apache-2.0:** maximises adoption, but allows proprietary forks; the owner wants copyleft.
- **GPL-3.0-only:** prevents upgrading to a future GPL version; "or later" is the FSF recommendation.
- **AGPL-3.0:** targets network services; Orchestra is a desktop application.

## Consequences

- Some useful crates (GPL-2.0-only, proprietary SDKs) are unavailable. The VST3 SDK has been
  dual-licensed MIT since 2025 (verify again when ADR-0011 is finalised).
- `cargo deny` runs locally and in CI, so a non-compliant dependency cannot be merged silently.
